

* Identities used for source and binary files

** Source Archive / Git verification

   - Archive Signature format (to differentiate from providers sig): filename.prs.whk.gpg.sig
   - Git
     - 3rd Party Git repos will have a tag added to the commit used using the following conventions
       - For a branch:  branchname-prs.whk.gpg.sig
       - For a tag:     tagname-prs.whk.gpg.sig
       - For a commit:  {git --short}.prs.whk.gpg.sig
     - Personal Git practice
       - commits will be signed by my Dev Key
       - tag : tbd
	 - Considerations:
	   - do I want some automated testing/verification before a signed tag
	   - do I want to personnaly sign each tag when ready for testing and then have build sign a separate tag when verified
   
   When a source archive or git repo is imported for use it will be signed
   by the appropriate identity to indicate the level of trust
   that I assign to it.

   IANAL Disclaimer:
     I make no claims about the trustworthyness of the files for
     other parties uses.  This only indicates the level of trust
     that I have in the source file.  Feel free to use as you wish
